# digit_dp · 超大数字筛选器

难度：L4。来源：原创教学题。

## 要交付什么

输入 N（0≤N≤10^18），输出 [0,N] 内十进制表示不含数字 4 的整数数量。0 计入。

## 自测样例（本仓库自编）

输入：
```text
20
```
输出：
```text
19
```

## 从枚举数字到枚举数位

朴素方法依次检查 0 到 N，把每个数字转换成字符串，判断是否含 `4`。它正确但 N 可达 10¹⁸，不可能逐个扫描。数位 DP 从高位到低位选择数字，合并“未来约束相同”的前缀。

状态 `(pos,tight)`：pos 是下一位的位置；tight 为真时前面各位都紧贴 N，当前位不能超过 N 对应位；tight 为假时前缀已经更小，当前位可选 0..9。选 4 的分支直接跳过。到最后一位以后得到一个合法数字。

## 样例逐步推演

N=20，把一位数统一补成两位来想：

- 十位选 0：个位可选 0..9 中除 4 的 9 个数，对应 0..9 中的合法数。
- 十位选 1：个位同样 9 个，对应 10..19 中的合法数。
- 十位选 2：仍紧贴上界，个位最多为 0，得到数字 20。

合计 `9+9+1=19`。其中 `00` 代表数字 0，题目要求把 0 计入。补前导 0 不会制造数字 4，所以本题不用额外记录是否开始；反例是“统计含数字 0 的正整数”：把 5 写成 05 会误以为它含 0，此时需要 started 状态并单独定义 0。缓存只复用 tight=false 的后缀，紧贴不同上界时不能混用。

<details><summary>提示与推导（先尝试再展开）</summary>

把 N 当作上界字符串，状态 (pos,tight) 表示前缀是否贴着上界。下一位只枚举允许数字。因为前导 0 不影响“是否含 4”，本题无需 started；换成统计数字 0 时就必须重新定义。

复杂度：时间 O(位数×10)，空间 O(位数)。

容易错在：把位数不足的数补前导 0，只对某些性质安全；本题包含数字 0。
