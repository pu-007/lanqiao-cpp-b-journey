# sum64 · 训练时长统计

难度：L0。来源：原创教学题。

## 要交付什么

输入 n（1≤n≤200000），再输入 n 个整数（绝对值≤10^9），输出它们的和。把训练日志的分钟数视为可正可负的修正记录。

## 自测样例（本仓库自编）

输入：
```text
4
1000000000 1000000000 -1 5
```
输出：
```text
2000000004
```

## 动手顺序

1. 先用纸笔推演样例，写出最直接的解法及操作次数。
2. 运行 `python3 scripts/lab.py start sum64` 生成你的独立答题文件；不复制参考实现。
3. 独立思考 20–40 分钟。卡住时只展开下面提示。
4. 运行 `python3 scripts/lab.py check sum64 --mine`；失败时先缩小反例。
5. 通过后再读 [sum64.cpp](sum64.cpp)，口述正确性与复杂度；2 天后关掉答案重写。

<details><summary>提示与推导（先尝试再展开）</summary>

从 0 开始逐项累加。循环读入第 i 项后，total 恰好是前 i 项之和。最大绝对和是 2×10^14，超过 int。

复杂度：时间 O(n)，额外空间 O(1)。

容易错在：结果使用 long long；不要先用 int 做乘法再赋给 long long。

### 更详细的推演

**怎么想到：** 不必存下全部记录，收到一条就把它加到当前总和，和手工记账一样。最简单的方法已经足够快。

**跟踪样例：** `total` 依次是 0 → 1000000000 → 2000000000 → 1999999999 → 2000000004。每完成一次循环，total 恰好等于已经读入的数之和；全部读完就得到答案。

**关键细节：** 20 万个数每个可能是 10^9，总和可达 2×10^14。比如三个 1000000000 的和是 3000000000，超过通常 32 位 int 的范围，因此累加变量必须是 long long。
