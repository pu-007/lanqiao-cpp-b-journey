# windowmax · 滑动峰值监控

难度：L3。来源：原创教学题。

## 要交付什么

输入 n k（1≤k≤n≤200000），再读 n 个绝对值≤10^9 的整数。输出每个长度 k 的连续窗口最大值。

## 自测样例（本仓库自编）

输入：
```text
6 3
1 3 -1 -3 5 3
```
输出：
```text
3 3 5 5
```

## 从暴力到更快的办法

最直接地对每个窗口扫描 k 个数求最大值，共 O(nk)。当 n 和 k 都很大时，邻近窗口反复扫描相同元素。单调队列记录“仍可能成为未来最大值”的候选下标，每个下标进队一次、出队最多一次，因此总时间 O(n)。

## 样例逐步推演

数字依次为 `1,3,-1,-3,5,3`，窗口长度 3。下面的队列按“值”展示，实际代码保存的是下标以判断过期：

| 新数 | 加入后的候选值（队首在左） | 完整窗口最大值 |
| --- | --- | --- |
| 1 | 1 | 尚未形成窗口 |
| 3 | 3 | 尚未形成窗口；1 被更大且更新的 3 淘汰 |
| −1 | 3, −1 | 3 |
| −3 | 3, −1, −3 | 3 |
| 5 | 5 | 5 |
| 3 | 5, 3 | 5 |

队首是未过期候选中最大值；新值不小于队尾时，队尾既更小又更早过期，再也不可能比新值更有用。若只存数值而不存下标，例如 `[5,1,5]`，不知道队首的 5 具体何时过期，会让删除逻辑产生歧义。不同约束若要求窗口中位数，单调队列不能直接解决。

<details><summary>提示与推导（先尝试再展开）</summary>

双端队列存候选下标，值从队首到队尾严格递减。新元素更大且更晚过期，会支配队尾较小元素；队首即最大值。

复杂度：时间 O(n)，空间 O(n)（输入数组；队列 O(k)）。

容易错在：队列保存下标才能判断过期；每个下标最多进出各一次，内层 while 不意味着 O(n²)。
