# 如何用这个仓库学习

## 一道题的闭环

1. **翻译题意**：用自己的话写输入、输出、允许动作、不能做什么，尤其是“连续/子序列”“恰好/至多”“有向/无向”。
2. **先做小规模**：写最直观的暴力并保留下来，它既可获得部分数据的正确结果，也能成为对拍基线。
3. **由约束提问**：n=20 可以枚举子集，n=200000 通常不行；输入有负数时滑动窗口还能用吗？
4. **再看一层提示**：卡 20–40 分钟后可看模型提示；先关闭提示自己写，不一次读完完整代码。
5. **验证**：样例→边界→自造反例→小随机暴力对拍。解释每个输出，不靠肉眼“感觉对”。
6. **延迟复写**：2 天、7 天、21 天后重做。会讲、会写、会迁移三项都满足才算掌握。

每周只有 8–10h，讲解或视频最多占约三分之一。花 2h 看懂一题、20min 抄完不算独立训练；宁可少做一题，把一个模型讲透。

## 项目式学习的边界

项目负责提供连续的需求变化：静态报表→批量修改→实时修改；迷宫等权路→加权路→最低铺线成本。每一步都回答“原算法为什么不够用了”。先交付算法程序，再做性能对比和迁移练习；暂不投入界面、配置系统和业务架构。

参考实现保持单文件、显式标准头文件，便于阅读和提交。一开始不要建立“万能算法库”，等你独立写过三遍再提炼个人模板。

## 记录有用的错误

错误按“读题、模型、证明、复杂度、边界、实现、时间分配”归类。例如“DP 错了”过于笼统；“一维 0/1 背包正序更新，导致一件物品重复选取”才可以复查。写下最小反例，下次复习先跑这个反例。

每周只追踪四个数字：独立首次通过数、提示后完成数、旧错题重做正确率、有效编码时间。题量是结果，不是唯一目标。

## 如何用 AI 和别人的题解

可以问“这个反例说明我的哪个假设错了”“只提示状态，不给代码”“检查复杂度推导”。独立练习和模拟期间先关闭答案生成；比赛是否允许相关工具以规程为准。读社区代码时主动检查类型、数组边界、递归深度、负权和重复边，不能因点赞多就当成正确证明。
