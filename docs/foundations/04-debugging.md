# 04 · 调试：从“结果错了”找到具体原因

## 一个真实的越界例子

`vector<int> a(n)` 有效下标是 0 到 n−1。如果写 `for (int i=0; i<=n; ++i)`，最后一次会访问 a[n]，这是越界。把 n=1 代入纸算，就能看到 i 依次是 0、1，而有效位置只有 0。

正确边界是 `i<n`。本地可以启用编译警告：

```bash
g++ -std=c++17 -Wall -Wextra -Wshadow -g your_file.cpp -o program
```

这里的文件名替换为你自己的文件。警告能发现部分问题，但不能证明代码一定正确。

## 每次 WA 的四步

1. **确认输入输出**：输出是不是多了提示文字？空格、换行、是否多组测试？
2. **缩小输入**：从失败的 100 个数里删去无关部分，直到剩下最小反例。
3. **手算变量**：每轮的 i、当前和、答案分别是多少？与程序输出到 `std::cerr` 的调试信息对比。
4. **修复原因**：写一句话解释错误，保留这个反例，运行原样例及边界，避免下次再犯。

例如你要数数组里等于 7 的数，输入 `3 / 7 7 1` 应输出 2。若只输出 1，观察循环是否在第一次找到 7 后提前结束。先确认原因，不要随机修改条件。

## 至少自己造这几类输入

| 类型 | 举例 | 会发现什么 |
| --- | --- | --- |
| 最小规模 | n=1、起点就是终点 | 初始化、边界 |
| 相同元素 | [2,2,2] | 重复计数、严格/非严格大小关系 |
| 极值 | 200000 个 10⁹ | int 溢出、空间与时间 |
| 无解或不可达 | 迷宫上下左右全封住 | 默认值与输出约定 |
| 题目允许的特殊值 | 0、负数、空串 | 隐含假设是否成立 |

只在题目允许的范围内构造测试。题目说正数时负数不是合法测试；但你应知道允许负数后原算法是否仍正确。

## 对拍：用慢而简单的方法查快算法

做小规模随机输入：让暴力程序和优化程序同时计算，比较输出。不同就打印输入，单独复现。比如双指针统计连续段，可以让暴力枚举左右端点并逐个求和；n 小时暴力慢一点也无妨。找到反例后要手算，确保暴力基线本身没有错。

参考仓库的 `python3 scripts/verify.py` 可以看到这样的做法；它验证的是参考程序。你自己的程序需要独立编译并用同样的输入运行。`python3 scripts/lab.py check ID --mine` 跑的是你的固定测试，不保证包含所有隐藏数据。
