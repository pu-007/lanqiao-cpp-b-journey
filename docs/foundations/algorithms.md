# 从零理解常见算法：先看问题，再选工具

如果你以前主要做软件开发，可以先把算法题当成一个小接口：输入一批数据，按规则返回答案。但除了功能正确，还必须看输入规模；同样正确的代码，数据一大可能运行不完。

这篇按“最直接的做法 → 出现的重复工作 → 如何优化”的顺序展开。第一次只读到二分或前缀和即可，剩下的在做题时回来查；不用背下每一段代码。

## 0. 做题时的通用五步

以“给 n 个数，找出它们的最大值”为例：

1. **说清楚输入、输出和限制**：n 个整数，输出最大值；要问 n 是否可能为 0、数字是否可能为负。
2. **自己造小例子**：`[-3, -1, -5]` 的答案是 `-1`。这能发现把最大值初始成 0 的错误。
3. **写最直接做法**：逐个检查，保存目前见过的最大值。n 个数要检查约 n 次。
4. **检查规模**：若 n 为十万，逐个检查通常没有问题；若每次询问都重扫一次，询问也有十万次，就有约 100 亿次检查，需要寻找重复工作。
5. **检验边界**：一个数、全部相同、全负、最大的合法输入，以及答案的数据类型。

一个算法通常要回答三个问题：**不漏**（合法答案都被考虑）、**不错**（输出确实符合要求）、**够快**（规模内做得完）。

## 1. 枚举：把可能性一一试过

题目：数组 `[2, 7, 4]` 中，有多少对不同位置的数之和是 6？

```text
下标对  (0,1)  (0,2)  (1,2)
数值对  (2,7)  (2,4)  (7,4)
和         9      6      11      所以答案是 1
```

写法是先选左位置 `i`，再选右位置 `j`；让 `j = i + 1` 开始，就保证不选同一位置，也不会把 `(0,2)` 和 `(2,0)` 算两次。

```cpp
int count = 0;
for (int i = 0; i < n; ++i) {
    for (int j = i + 1; j < n; ++j) {
        if (a[i] + a[j] == target) ++count;
    }
}
```

这是片段，假设 `a`、`n`、`target` 已经输入。它的检查次数是 `n*(n-1)/2`，记作 O(n²)。元素允许重复时，**位置不同**的方案仍要分别算；如果题目要求不同数值，计数规则就变了。两数相加可能超 int 时，先将数组或运算转成 `long long`。

**什么时候使用？** n 很小，或者在研究更快算法之前，先写一个可信的慢解，之后用它验证优化版。[数字筛选器](../../projects/00-basics/digit_filter.md)就是逐个枚举并判断。

试一试：`[1,1,2]`、目标 3，按位置计数答案是几？
<details><summary>答案</summary>2：第一个 1 与 2 一对，第二个 1 与 2 另一对。</details>

## 2. 排序：先让数据有秩序

题目：数列 `5 2 8 2` 的中间两个数是什么？先排序得到 `2 2 5 8`，答案是 2 和 5。排序并不直接解决所有问题，但它能让“相同的挨在一起”“左右大小有关系”，为去重、二分、双指针和贪心创造条件。

```cpp
#include <algorithm>
#include <vector>

std::vector<int> a = {5, 2, 8, 2};
std::sort(a.begin(), a.end()); // 此时 a 为 {2, 2, 5, 8}
```

`begin()` 到 `end()` 表示左闭右开范围 `[begin, end)`；`end()` 指向最后元素后面，不可解引用。`sort` 常用时可按 O(n log n) 估算，**会修改原数组**。如果题目要求原始下标，可排序 `(数值, 原下标)`，或复制数组后排序。

需要自定义顺序时，比较器回答“a 应当排在 b 前面吗”：

```cpp
std::sort(a.begin(), a.end(), [](int x, int y) {
    return x > y; // 降序；相等时必须返回 false，不能写 >=
});
```

**什么时候使用？** 要比较相邻元素、查询范围、处理重复值，或证明某种按顺序选择的策略时。练习：[训练排行榜](../../projects/01-stl/ranking.md)，观察多关键字排序如何处理同分。

## 3. 二分查找：每次排除一半候选

假设已排序数组是 `[2, 4, 4, 7, 9]`，查找第一个不小于 4 的位置：

```text
下标       0  1  2  3  4
值         2  4  4  7  9
是否 >=4   否 是 是 是 是
              ↑ 第一个“是”，答案下标为 1
```

这里真正利用的是“答案的性质从否变成是，而且之后不再变回否”。先看中间，若中间是“是”，答案可能在中间或左边；否则答案只能在右边。

标准库写法：

```cpp
// a 必须已经从小到大排序。
auto it = std::lower_bound(a.begin(), a.end(), 4);
if (it == a.end()) {
    // 没有任何元素 >= 4；不要解引用 it。
} else {
    int index = static_cast<int>(it - a.begin());
}
```

自己写时可以用半开区间 `[lo, hi)`：

```cpp
int lo = 0, hi = static_cast<int>(a.size());
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] >= target) hi = mid; // mid 可能就是第一个，保留
    else lo = mid + 1;              // mid 和左侧都不满足
}
// lo == a.size() 表示找不到；否则 lo 是第一个 >= target 的位置。
```

注意：空数组、全部小于目标、重复值都应测试。二分并不是“看到数组就能用”：无序数据中性质可能是“否、是、否”，直接二分会漏答案。

### 二分答案：不查数组，而是猜一个数

运输容量为 C 时，判断能否在规定天数内运完。如果容量 6 可以，那么容量 7、8 通常也可以；性质类似 `不可行、不可行、可行、可行`。因此可二分**最小可行容量**。关键是先证明“可行性随容量单调”，再写判断函数。[最小运输容量](../../projects/03-decisions/capacity.md)按这个过程讲解。

试一试：数组 `[1,3,3,8]`，第一个不小于 3 的下标是多少？如果找 9 呢？
<details><summary>答案</summary>分别是 1 和 4；4 等于数组长度，代表没有符合条件的元素。</details>

## 4. 前缀和：把重复加法先做好

题目：每天的训练分钟为 `[2, -3, 5, 7]`，多次询问从第 l 天到第 r 天的总和。最直接方法是每次从 l 加到 r；当询问很多时，大量重复。

先求“前 i 天总和”，第 0 天之前为 0：

```text
天数 i       0   1   2   3    4
当天值           2  -3   5    7
前 i 天和    0   2  -1   4   11
```

第 2 到第 4 天的和：`前4天 - 前1天 = 11 - 2 = 9`。前 1 天是多出来的部分，所以应该减掉。

```cpp
std::vector<long long> prefix(n + 1, 0); // prefix[0] 是 0
for (int i = 1; i <= n; ++i) {
    long long x;
    std::cin >> x;
    prefix[i] = prefix[i - 1] + x;
}
// 题目中 l、r 从 1 开始，并满足 1 <= l <= r <= n。
long long answer = prefix[r] - prefix[l - 1];
```

预处理 O(n)，一次求和 O(1)，额外存 O(n)。元素可正可负；负数不会让前缀和公式失效。缺点是修改了某一天后，其后的前缀都要更新。这里的差分思想针对“批量修改后最后查询”；树状数组则可以处理在线修改与查询。

**什么时候使用？** 静态数组有很多区间和查询；或题目需要快速得到某一段和。[静态区间报表](../../projects/02-range/prefix.md)提供完整输入输出与测试。

## 5. 双指针 / 滑动窗口：两个边界共同向前走

题目：数组 `[1, 2, 0, 3]` 中，统计和不超过 3 的非空连续子数组。数组所有数都**非负**。

想象一扇窗，左右边界是 `left` 和 `right`。右边往右移动时把新值加进来；如果窗口和超过 3，就把左边移走直到重新合法。对每个右端点，`left` 到 `right` 内每个位置都能作合法起点。

```text
right=0: [1]          合法起点 0                 新增 1 个
right=1: [1,2]        合法起点 0、1              新增 2 个
right=2: [1,2,0]      合法起点 0、1、2           新增 3 个
right=3: [0,3]        原窗和 6；移走 1、2 后合法   新增 2 个
总数：1+2+3+2=8
```

为什么移走左侧可以使窗口和不增加？因为每个数都非负。右边和左边都只向前走，最多各走 n 次，因此总时间是 O(n)，不是 O(n²)。完整程序看[预算内连续训练段](../../projects/02-range/window.md)。

有负数就不能照搬：`[5,-5]`、K=0，在处理第一个 5 时若把它移掉，就会漏掉后续合法窗口 `[5,-5]`。**连续子数组**要求位置相邻，不能与可以跳过元素的“子序列”混淆。

## 6. 贪心：每一步先做一个经过证明的选择

题目：一间会议室，最多安排多少场互不冲突的会议？会议分别是 `[0,3)`、`[1,2)`、`[2,4)`。区间右端不包含在会议时间内，所以前一场结束时后一场可以立即开始。

```text
0       1       2       3       4
|-------[  A    ]-------|
        |-- B --|-- C --|
```

选 A 只能安排 1 场；选 B、C 可以安排 2 场。直觉上，**先选结束最早的会议**能给后续留出更多时间。

为什么它可靠？假设某个最优方案第一场不是结束最早的 B，把那第一场换成 B：B 不会结束得更晚，所以原方案后面的会议仍能照常安排，会议总数不减。于是存在一个最优方案以 B 开头；对剩余时间重复同样推理。这叫交换论证。

注意这个证明只解决“会议数最多”。若每场会议收益不同，选结束最早的可能错；例如 `[0,2)` 收益 1、`[0,3)` 收益 100。题目改变，结论也要重新证明。完整练习：[会议室预约](../../projects/03-decisions/intervals.md)。
