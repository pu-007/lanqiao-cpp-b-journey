# 搜索、动态规划和图：从小例子入门

这三类知识都在回答“从当前情况出发，接下来能发生什么”。建议先按顺序看例子，自己画一遍，再去运行每节末尾的仓库练习。文中涉及的下标没有特别说明时从 0 开始。

## 1. DFS：沿一条路走到底，再退回来

假设有两件装备 A、B，每件有“选”和“不选”两种选择。把所有可能画成树：

```text
                  开始
             /            \
          不选 A           选 A
          /   \            /   \
      不选 B  选 B      不选 B  选 B
        {}     {B}        {A}    {A,B}
```

深度优先搜索（DFS）就是先走到一片叶子，例如 `{}`，记录结果，然后退回上一层走 `{B}`。退回时如果改变过共享状态，要把它恢复原样，这称为**回溯**。例如向 `path` 放入 A 后，探索完“选 A”的所有情况，要 `pop_back()`，否则之后的其他分支也会带着 A。

下面是可单独编译运行的示例，依次输出子集和 0、2、1、3：

```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<int> weight = {1, 2};

void dfs(int index, int sum) {
    if (index == static_cast<int>(weight.size())) {
        cout << sum << '\n'; // 每件装备都已决定，在叶子记录一次
        return;
    }
    dfs(index + 1, sum);                 // 不选当前装备
    dfs(index + 1, sum + weight[index]); // 选当前装备
}

int main() {
    dfs(0, 0);
    return 0;
}
```

`index` 告诉我们下一件要考虑什么，`sum` 是已选重量。它们按值传入，每次调用得到自己的副本，因此此例不需要手动撤销 `sum`。如果有 n 件装备，每件两种选择，叶子数是 2ⁿ；n 很大时就需要别的办法。

动手：[装备组合搜索](../../projects/04-search/subsets.md)。特别试试目标和为 0、装备重量为 0 时，为什么找到一个满足的中间状态后不能直接结束搜索。

## 2. BFS：一圈一圈扩展，找等权最短路

把迷宫想成一张格子地图，每次只能上下左右走一格，每一步成本都是 1。广度优先搜索（BFS）先看距起点 1 步的格子，再看 2 步的格子……第一次抵达终点时，用的步数就是最少的。

```text
地图          距离（# 是墙）
S . .         0 1 2
. # .         1 # 3
. . T         2 3 4
```

用队列维护“已经发现、等待处理”的格子：

1. 起点距离设为 0，放入队列。
2. 取出队首，尝试上下左右四个邻居。
3. 合法且未访问的邻居，距离设为当前距离加 1，**立刻标记并入队**。
4. 队列空时结束。没被访问的格子不可达。

为什么入队时就标记？两个相邻格子可能同时发现同一个新格子；如果等出队才标记，新格子会被重复放入队列。BFS 的前提是每一步成本相同；如果有的路耗时 1、有的路耗时 10，单纯按步数分层就不能保证最短时间。

可运行的图上 BFS（输入 `n m s`，随后 m 行无向边，点编号 1 到 n）：

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    int n, m, start;
    if (!(cin >> n >> m >> start)) return 0;
    vector<vector<int>> graph(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        graph[v].push_back(u); // 无向边需要存两个方向
    }
    vector<int> distance(n + 1, -1); // -1 表示还没有发现
    queue<int> q;
    distance[start] = 0;
    q.push(start);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : graph[u]) {
            if (distance[v] != -1) continue;
            distance[v] = distance[u] + 1;
            q.push(v);
        }
    }
    for (int i = 1; i <= n; ++i) {
        if (i > 1) cout << ' ';
        cout << distance[i];
    }
    cout << '\n';
    return 0;
}
```

试输入 `4 3 1`，边依次为 `1 2`、`1 3`、`3 4`，输出是 `0 1 1 2`。孤立点应输出 `-1`。时间和空间都是 O(n+m)：每个点、每条边只处理常数次。

动手：[迷宫导航器](../../projects/04-search/maze.md)，先求最短步数，再尝试记录“从哪个格子走过来”还原路径。DFS 也能找到一条路，但**第一条找到的路不一定最短**。

## 3. 图：把事物和关系画出来

图并不神秘：**点**代表事物，**边**代表关系。城市和道路、课程和先修关系、账号和好友关系都可以建模成图。

```text
    2
1 ------ 2
 \      /
  5\  /1        4（孤立点）
    3
```

上图的数字 1、2、3、4 是点，边上的 2、5、1 可表示距离或费用。注意无向图的一条边是双向的；有向边 `u → v` 不保证可以从 v 返回 u。图可以有重边、自环或不连通分量，必须读题确认。

对于 n 个点、m 条边，邻接表 `vector<vector<int>> g(n+1)` 记录每个点能直接到达的邻居，通常占 O(n+m) 空间。比如边 `1—2` 存两次：`g[1].push_back(2)` 和 `g[2].push_back(1)`。如果边有权重，就存 `(邻居,权重)`。

先问清楚题目目标，再选工具：

| 题目问什么 | 一个常见工具 | 前提或提醒 |
| --- | --- | --- |
| 哪些点互相可达、共有几个圈子？ | DFS/BFS 或并查集 | 并查集适合不断加边和查询连通性 |
| 从起点走到终点最少经过多少条边？ | BFS | 每条边代价相同 |
| 从起点到各点的最低距离？ | Dijkstra | 边权非负；默认最小堆需配置比较器 |
| 连通所有点的最低铺线总价？ | Kruskal | 目标是所有点连起来，和单源最短路不同 |

例如：三条边 `1—2` 权 2、`2—3` 权 2、`1—3` 权 3。从 1 到 3 的最短距离是 3；连通全部点的最小铺线总价是 4（选前两条边）。**问的问题不同，答案也不同。**

动手：依次完成 [并查集](../../projects/05-graphs/dsu.md)、[最短路](../../projects/05-graphs/dijkstra.md)、[最小生成树](../../projects/05-graphs/kruskal.md)。先画 3～4 个点的图，再写代码。

## 4. DP：把重复出现的小问题记下来

你一次可以爬 1 阶或 2 阶，问爬到第 n 阶有多少种走法。先不用代码，手算：

| 阶数 n | 可行走法 | 数量 |
| --- | --- | --- |
| 0 | 什么也不走 | 1 |
| 1 | 1 | 1 |
| 2 | 1+1；2 | 2 |
| 3 | 1+1+1；1+2；2+1 | 3 |
| 4 | 从第 3 阶迈 1 步，或从第 2 阶迈 2 步 | 5 |

定义 `dp[i]` 为“爬到第 i 阶的走法数”。最后一步只能来自 `i-1` 或 `i-2`，且两类走法不会重叠，所以 `dp[i] = dp[i-1] + dp[i-2]`。边界 `dp[0]=1` 的意思是“在起点不走也是一种空方案”，不是说爬了一级。

下面程序输入 n（0≤n≤90），输出走法数；这个范围内结果可用 `long long` 保存：

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    if (!(cin >> n)) return 0;
    vector<long long> dp(n + 1, 0);
    dp[0] = 1;
    if (n >= 1) dp[1] = 1; // n=0 时不能访问 dp[1]
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    cout << dp[n] << '\n';
    return 0;
}
```

输入 `4`，输出 `5`。看起来只是把数列填进数组，但最重要的动作是：**决定数组的每一项究竟代表什么**。

碰到一道 DP 题，先回答四个问题：

1. **状态**：`dp[i]` 或 `dp[i][j]` 精确代表什么？包含还是不包含第 i 个元素？
2. **选择**：最后一步可能是什么？这些情况是否覆盖全部方案、彼此是否重复？
3. **初始值**：没有元素、容量为 0、无法到达时各是什么？
4. **计算顺序**：需要的旧状态算出来了吗？用一维数组时是否覆盖了还要用的旧值？

## 5. 从“爬楼梯”到 0/1 背包

背包容量为 5，有物品 A（重量 2，价值 3）和 B（重量 3，价值 5），每件最多拿一次。每个容量对应“重量不超过这个容量时的最大价值”：

| 已处理物品 | 容量 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 3 | 3 | 3 | 3 |
| A、B | 0 | 0 | 3 | 5 | 5 | 8 |

容量为 5 时，不选 B 价值是上一行的 3；选 B 则剩余容量 2，价值为上一行的 3 加上 B 的 5，得到 8。取二者较大值。

压成一维时必须**从大容量往小容量更新**。以单件 A 为例，如果容量从 2 正序扫到 4，刚写出的 `dp[2]=3` 又被用来算 `dp[4]=6`，等于错误地拿了两次 A。倒序能确保读到的是处理 A 之前的值。

动手：[训练收益规划](../../projects/06-dp/knapsack.md)。先手画上述二维表，再写一维；之后尝试 [砝码称重真题](../../solutions/past-papers/real_weights.md)，体会“把物品放到两边”比普通背包多了什么选择。

- 能给每题造至少一个边界：起点即终点、不可达、只有一个点、容量为 0、重复数值。
