# 01 · 复杂度：为什么有的程序会超时？

## 先想象两个找人的方法

名单有 n 个人，想找是否有小明。最直接的方法是一个个看：最倒霉可能看 n 次。如果每个人都要和其他每个人握手比较一次，就可能看大约 n² 对人。人数从 100 增到 100,000 时，第二种方法的工作量增长快得多。

**时间复杂度**粗略描述输入规模增大时，操作次数怎样增长；它不是实际秒数。C++ 编译优化、机器、每次操作的代价、题目时间限制都会影响运行时间。

## 一眼看循环

```cpp
for (int i = 0; i < n; ++i) { /* 一次常数工作 */ }
```

执行 n 次，记为 **O(n)**，念“线性”。

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) { /* 一次常数工作 */ }
}
```

外层 n 次，每次内层 n 次，合计 n×n，记 **O(n²)**。如果内层只有 `j < i`，总次数约 n(n-1)/2，增长量级仍是 O(n²)。

顺序执行一个 O(n) 循环和一个 O(n²) 循环，总量 n+n²，规模很大时 n² 增长更快，通常写 O(n²)。但“有两层循环”不一定是 O(n²)：例如双指针中两个指针各只向右走 n 步，需要逐个数指针移动次数。

| 输入规模 n | n | n² | 2ⁿ | 常见方向（只是粗略筛选） |
| --- | ---: | ---: | ---: | --- |
| 20 | 20 | 400 | 1,048,576 | 可考虑枚举子集 |
| 1,000 | 1,000 | 1,000,000 | 非常大 | 可考虑平方级算法 |
| 100,000 | 100,000 | 10,000,000,000 | 极大 | 优先线性或接近线性 |

排序通常 O(n log n)，比平方增长慢；二分每次把候选范围约缩一半，循环约 log₂n 次。估算只能帮你排除明显太慢的方法，不能保证符合某道题的具体时限。

## 空间复杂度和整数类型

长度为 n 的 `vector<int>` 大约存 n 个整数，使用 O(n) 空间；n 行 m 列的数组使用 O(nm) 空间。若函数递归 n 层，还要考虑调用栈的 O(n) 空间。

题目若给出 200,000 个数，每个最多 10⁹，最大总和是 2×10¹⁴。常见 `int` 放不下，应该用 `long long`。先计算范围，再定类型；`1LL * a * b` 可以让乘法从一开始就在 `long long` 中进行。它仍有上界，不能容纳无限大的结果。

## 自己试一试

1. 读 n 个数并求最大值需要几次比较？为什么不用排序？
2. 遍历 n×m 网格的每格一次，时间和空间分别是什么？
3. 一个数组中枚举所有 `(i,j)`，且要求 `i<j`，大约有多少对？

<details><summary>核对思路</summary>

1. 扫描一次 O(n)，只保存最大值可用 O(1) 额外空间。排序通常 O(n log n)，为求一个最大值做了额外工作。
2. 时间 O(nm)；如果保存整个网格，空间 O(nm)，若题目允许边读边处理则可能只用 O(1) 额外空间。
3. n(n−1)/2 对，时间 O(n²)。

</details>
